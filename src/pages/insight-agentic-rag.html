Introduction

Retrieval-augmented generation (RAG) has become the standard pattern for grounding large language models in real-world knowledge. But basic RAG pipelines retrieve once and generate once, which breaks down when questions are complex, multi-hop, or require reasoning across multiple sources. Agentic RAG adds a planning layer that decomposes questions, selects retrieval strategies, evaluates intermediate results, and synthesizes answers with citations.

This article covers the architecture of a production agentic RAG system, from source ingestion through evaluation and monitoring. The patterns described here are based on real implementation work across knowledge management, customer support, and internal operations use cases.

Source Ingestion and Access Control

Every agentic RAG system begins with reliable source access. A production system needs connectors for SQL databases, REST APIs, cloud storage, CMS platforms, and internal wikis. Each connector must enforce role-based access control so the retrieval layer never surfaces documents a user is not authorized to see.

Incremental synchronization keeps indexes fresh without full re-ingestion. Webhook listeners trigger re-indexing when source content changes. Document processing handles PDFs, Word files, HTML pages, spreadsheets, and slide decks through a configurable chunking pipeline that splits documents into overlapping segments of 256 to 1,024 tokens, preserving paragraph boundaries and section headings.

Each chunk carries metadata including source URL, author, publication date, department, and content type. This metadata enables filtered retrieval and citation generation downstream. The chunking strategy matters: too aggressive and you lose context; too conservative and you waste context window budget on irrelevant content.

Hybrid Retrieval Architecture

Single-mode retrieval misses relevant content. A production architecture combines BM25 keyword search for exact term matches with dense vector similarity for semantic understanding. A learned sparse retrieval layer adds term-weighting that adapts to the corpus.

Results from all three channels are merged using reciprocal rank fusion, then passed through a cross-encoder reranker that scores each candidate against the original query. The reranking stage typically improves top-5 precision by 15 to 30 percent over unranked retrieval. The system supports configurable top-k values, minimum score thresholds, and diversity constraints that prevent multiple results from the same source document from dominating the context window.

Vector embeddings should be generated using models that match your domain. General-purpose embedding models work for broad knowledge bases, but domain-specific fine-tuning improves retrieval quality for specialized corpora like medical literature, legal documents, or technical documentation.

Agent Planning and Answer Synthesis

Simple RAG pipelines retrieve once and generate once. Agentic RAG adds a planning layer that decomposes complex questions into sub-queries, retrieves for each, evaluates intermediate results, and synthesizes a final answer. The planner uses tool-calling patterns to invoke retrieval, web search, database queries, or calculator functions as needed.

Answer synthesis follows a structured prompting pattern: the model receives the query, retrieved passages with source attribution, and instructions to cite each claim. Unsupported claims are explicitly marked. Confidence scores are assigned at the sentence level, and low-confidence passages trigger additional retrieval rounds or clarification prompts rather than speculative generation.

The agent should also handle follow-up questions and conversational context. Session memory tracks the conversation history so the agent can refine its retrieval strategy based on what the user has already asked and what information has already been provided.

Citation Validation and Hallucination Controls

The most critical quality metric for a RAG system is faithfulness: every claim in the generated response must be grounded in the retrieved context. Citation validation checks that each generated statement can be traced to a specific passage in the retrieved documents.

Implementation patterns include: sentence-level claim extraction, passage matching using semantic similarity, contradiction detection between claims and source passages, and confidence scoring that flags low-evidence statements. Unsupported statements are either suppressed, marked with a confidence warning, or trigger additional retrieval rounds.

Production systems should track hallucination rates over time. A sudden increase may indicate stale source content, embedding drift, or retrieval degradation. Automated faithfulness checking using an LLM-as-judge approach provides continuous monitoring without manual review of every response.

Evaluation Framework

The evaluation framework tests three dimensions: retrieval quality, answer faithfulness, and end-to-end utility. Retrieval quality measures recall@k, precision@k, and mean reciprocal rank against a labeled test set of 200 or more questions. Answer faithfulness uses an LLM-as-judge approach to verify that every claim in the generated response is grounded in the retrieved context.

End-to-end utility measures task completion: did the answer resolve the question, was it cited correctly, and did it arrive within the latency budget? The system tracks these metrics continuously and surfaces regressions in a quality dashboard. Common failure modes include chunking boundary errors, stale source content, and reranker overconfidence on ambiguous queries.

Production Monitoring

Once deployed, the system needs continuous monitoring across several dimensions: retrieval quality (are relevant documents being found?), answer quality (are responses accurate and useful?), latency (are responses arriving within acceptable time?), and cost (are token budgets being managed effectively?).

Source freshness tracking ensures the knowledge base stays current. Documents that change frequently need more frequent re-indexing. TTL policies prevent stale content from being retrieved. Priority re-indexing handles high-velocity content like news feeds or product catalogs.

Implementation Considerations

Chunk size optimization: The optimal chunk size depends on the source content and the retrieval strategy. Shorter chunks (256 tokens) improve precision but may lose context. Longer chunks (1024 tokens) preserve context but waste context window budget. Overlapping chunks with 50-100 token overlap provide a good balance.

Embedding model selection: General-purpose models like text-embedding-3-small work for broad knowledge bases. Domain-specific fine-tuning improves retrieval quality for specialized content. The embedding model should be versioned and evaluated alongside the retrieval system.

Context window management: The retrieved passages must fit within the LLM context window while leaving room for the query, instructions, and generated response. A typical production system retrieves 5-10 passages of 512 tokens each, using approximately 50% of a 32K context window for retrieved content.

When to Use Agentic RAG

Agentic RAG is most valuable when: questions require reasoning across multiple sources, the knowledge base is large and diverse, users need cited and verifiable answers, the domain requires high accuracy, or the system needs to handle follow-up questions and conversational context. For simpler use cases, a basic RAG pipeline may be sufficient and more cost-effective.

Frequently Asked Questions

How is agentic RAG different from basic RAG?

Basic RAG retrieves documents once and generates a response. Agentic RAG adds a planning layer that decomposes complex questions, retrieves for each sub-query, evaluates intermediate results, and synthesizes answers with citations. This produces more accurate, traceable, and useful responses for complex queries.

What data sources can be connected?

Production agentic RAG systems connect to SQL databases, REST APIs, cloud storage, CMS platforms, internal wikis, PDFs, spreadsheets, and email systems. Each connector enforces access controls and supports incremental synchronization.

How do you prevent hallucinations?

Hallucination prevention uses citation validation (every claim is checked against retrieved passages), confidence scoring (low-confidence statements are flagged), and retrieval-then-verify loops (uncertain answers trigger additional retrieval rounds). Automated faithfulness checking provides continuous monitoring.

What evaluation metrics matter most?

The three key dimensions are retrieval quality (recall@k, precision@k), answer faithfulness (percentage of claims grounded in source passages), and end-to-end utility (task completion rate, latency, and user satisfaction). All three should be tracked continuously in a quality dashboard.
